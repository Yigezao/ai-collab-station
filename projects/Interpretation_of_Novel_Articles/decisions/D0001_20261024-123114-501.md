# UI v2 口径裁决：全盘只读浏览、静态页面拆分、第4步绑定表格、产物来源标注

# 决策：UI v2 方案口径（第 3 轮讨论收口）

## 背景与结论

用户追加需求（E000389，项目已 reopen E000390）：直接浏览选择文件、想要什么操作直接选择（附说明）、尽量不写代码、接口清晰、每个产出地址与检索口径写清楚。

第 3 轮：S01 提案（E000393，`discussion/rounds/R0003_S01_20261024-122727-046.md`）推荐选型 A；S02 评审（E000398，`discussion/rounds/R0003_S02_20261024-123001-026.md`）投 A 并提出 3 项实质修正。两票 A、无反对。总管裁决如下，写入方案 v2。

## 已达成共识（直接采纳）

1. **选型 A**：服务端只读目录浏览 API + 结构化字段 + `ui/specs.py` 单一数据源。B（上传复制到 `data/uploads`）与 C（系统文件对话框）v2 不引入；B 的代价是产生副本、`source_id` 退化为 `local:<文件名>`、原始绝对路径丢失，且需分片/上限/清理/冲突等新增代码面；C 依赖桌面会话、服务线程弹窗易卡死、无法自动测试。
2. **不改模块契约**：`source` / `segmentation` / `script` / `audio` / `video` 的 CLI、JSON 字段、manifest、退出码全部不动；零新依赖；第 3 步仍 mock；第 4 步仍人工绑定、不自动配音；不宣称真实 ffmpeg 编码已验证。
3. **覆盖保护**：UI 永不自动加 `--force`；`confirm_overwrite` 未勾选时服务端拒绝；模块自身“目标已存在/非空默认拒绝”仍是硬闸门。
4. **运行与并发**：同一时刻只运行一个模块子进程（进程内锁），并发返回 `BUSY`；保留 300s/600s 超时并映射为 `failed`。
5. **安全**：只绑 `127.0.0.1`；校验 Host（带端口，仅 `127.0.0.1`/`localhost`）；POST 必须 `Content-Type: application/json` 且带 `X-UI-Request: 1`；带 `Origin` 时必须为同源 loopback，否则 403；不返回 CORS 头。

## 分歧裁决

### D1 浏览边界：全盘只读，不做白名单（采纳 S02）

- 理由：用户稿件常在桌面/下载/其它盘，白名单要么退化为全盘、要么每换目录就要改配置，与“尽量不写代码”直接冲突。白名单宣称的收益（防本机其它页面读取目录名）真实入口是跨站请求，已由 Host/Origin/自定义头/无 CORS 覆盖；对同机同用户进程，白名单也挡不住。
- 硬约束（缺一不可，写入任务验收）：只返回元数据、不返回文件内容；单层、不递归、上限 2000 条；路径必须绝对且 resolve 后存在，拒绝相对路径/空串/NUL/控制字符，结构化错误码 `INVALID_INPUT`/`NOT_FOUND`/`NOT_A_DIRECTORY`/`PERMISSION_DENIED`，不静默回退 cwd；默认隐藏 Windows hidden 属性与点文件并给“显示隐藏项”开关；提供盘符根/主目录/桌面/下载/项目根/data/library/最近使用快捷入口；junction/符号链接只作条目返回、不展开，单条 stat 失败跳过并写入 `warnings`。
- 风险如实写入 README：无认证 loopback 服务，任何本机进程均可调用；若出现跨站读取迹象，先加启动随机 token，再考虑收紧。

### D2 页面结构：拆静态文件（采纳 S02，否决 S01 §8 单文件）

- 采用 `ui/static/index.html` + `app.js` + `app.css`，server 用**固定映射表**服务（不接受用户路径，无目录遍历面）；`render_page()` 保留，改为读取模板后做 **token 替换**（不使用 `str.format`）；静态文件缺失时返回 500 + 明确信息，不返回空白页。
- 理由：页面要装 spec 渲染、浏览弹窗、绑定表格、产物卡片、运行记录，内嵌 Python 字符串后所有 JS 花括号都需转义，编辑器语法检查失效，维护风险高于 +3 文件 +1 固定路由的代价。
- 冻结 token：`%%DISCLAIMER%%`、`%%EXIT_CODES%%`、`%%SEARCH_INFO%%`、`%%PROJECT_ROOT%%`、`%%LIBRARY_PATH%%`、`%%STEP_NAV%%`。JS 运行时从 `/api/spec` 取表单定义，不把 specs 复制进页面。

### D3 第 4 步绑定：绑定表格（采纳 S02）

- 服务端只读用户选中的 `index.json`，取 `segments[].seg_id` 渲染“段号｜seg_id｜音频文件（浏览选择）”表格；提交时直接构造重复 `--binding seg_id=绝对路径`，用户全程不写 bindings.json。
- `index.json` 读取失败时退回仅文件方式（`bindings` 字段）并明确提示，不猜测；读 index 只用于列 seg_id，不重写模块校验（段数不一致/重复/多余仍由模块拒绝）。
- 保留 `bindings`（文件）作为高级替代方式。

### D4 产物路径来源：必须标注（采纳 S02）

- 产物卡片逐项标注来源：**模块 JSON 字段** 或 **库布局推导**。`variants` 操作不返回 comparison.json 路径，按 `<library>/<work_id>/comparison.json` 推导，必须标注“布局推导”。
- hash 默认目录（`segments/run-<hash>`、`script/run-<hash>`）不重算、不编造：只显示父目录 + 命名规则 + “运行后确定”，运行后回填实际路径。每一步都允许显式指定输出目录以得到精确预览。

### D5 库位置统一（采纳 S02）

- 页面只设一个“库位置”字段，默认 resolve 为项目根下 `data/library` 的绝对路径并显示；第 1 步 `--library` 与第 2 步 `--library-dir` 映射同一 UI 值，避免换库后两步不一致导致产物“找不到”。

### D6 `--source-args`（采纳 S01+S02 共同口径）

- 保留兼容但标注 deprecated；结构化字段与 `--source-args` 同时出现直接 `INVALID_INPUT`；下一版移除。UI 不再发送参数串。

## 落选方案与重评条件

| 落选方案 | 落选理由 | 重评条件 |
|---|---|---|
| B 上传复制 | 产生副本、来源追溯变差、新增代码面，对“浏览选择”无增益 | 用户明确要“拖拽上传/远程浏览器”，且必须把 source_id 与原始文件名写入 provenance |
| C 系统文件对话框 | 服务线程弹窗卡死、无桌面不可用、无法自动测试 | 不做（与 A 收益重叠） |
| 白名单浏览 | 与“不写代码”冲突，安全收益已被 CSRF/Host/Origin 覆盖 | 出现跨站读取迹象或用户要求收紧 |
| 单文件页面（str.format） | 转义脆弱、无法语法检查 | 若静态路由引入不可接受复杂度（需总管复审） |
| 手写 bindings.json | 违背“尽量不写代码” | 若评审认为服务端读输入文件越界，退回“生成模板”按钮 |
