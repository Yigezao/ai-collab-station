## 正文

T013 交付：项目根目录 start_ui.bat（Windows 双击启动五步工作流 UI）与 README「一键启动 UI」小节。

一、交付内容
1. start_ui.bat（新增，纯 ASCII、CRLF）：chcp 65001 + PYTHONUTF8=1/PYTHONIOENCODING=utf-8；cd /d "%~dp0" 定位项目根；可选端口参数（默认 8765）；启动前检查端口占用；优先 python、回退 py -3；前台运行 python -m ui.cli serve --port N（关闭窗口/Ctrl+C 即停，不留后台进程）；后台 PowerShell 轮询 TCP 就绪后 Start-Process 打开 http://127.0.0.1:N/；各失败分支输出中文并 pause。
2. README.md：在「安装与运行」内新增「### 一键启动 UI（Windows 双击启动）」，说明双击运行、默认地址、关闭方式、换端口、找不到 Python 的处理。

二、实现说明（重要）
- 脚本全文保持 ASCII：实测 cmd.exe 解析含中文的 UTF-8 批处理时会把部分行截断、尾部被当作命令（复现：原中文版把「关闭本窗口（服务随之停止）。」报为内部命令）。因此中文提示以 UTF-8 base64 存放在 bat 内，由 :say 子程序经 PowerShell 按 UTF-8 输出；文件头注释说明修改提示需重新 base64。
- 未改动任何业务模块、ui/* 服务端代码或依赖，未触碰 scope 外文件。

三、实测（2026-10-24，本机）
1. 正常启动：start_ui.bat 18765 → 输出中文启动提示；curl http://127.0.0.1:18765/ 返回 HTTP 200，页面含「来源导入/章节截取/解说文案/外部音频导入/视频合成」五个步骤标题。
2. 端口占用：start_ui.bat 8765（该端口由用户现有 UI 占用，PID 17156）→ 退出码 3，中文提示含 http://127.0.0.1:8765/ 与换端口方法，未启动第二个服务。
3. 非法端口：start_ui.bat abc → 退出码 2，中文提示，pause。
4. 找不到 Python：临时把 PATH 限制为 System32/Windows/WindowsPowerShell 后运行 → 退出码 1，中文提示，pause。
5. 中文路径：脚本复制到 D:\Temp\中文路径测试（含最小 ui 桩模块）运行 → 输出 cwd=D:\Temp\中文路径测试、argv=serve --port 18769 正确，中文提示无乱码。
6. 停止与僵尸：taskkill 终止 serve 后 18765 无 LISTENING 残留；脚本走失败分支输出中文并 pause（真实 Ctrl+C 由 ui/cli.py 捕获 KeyboardInterrupt 返回 0，走「UI 已停止」）。
7. 编码：start_ui.bat 无 BOM、无非 ASCII 字节、全 CRLF；README 中文正常。
8. 浏览器自动打开：PowerShell 轮询逻辑对运行中的 8765 首次连接成功；正常启动测试时段系统出现新 msedge 进程（PID 25960，09:49:17），但窗口是否可见无法在无头环境断言。
