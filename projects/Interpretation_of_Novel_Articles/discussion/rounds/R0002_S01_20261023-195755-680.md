# S01 第 2 轮：U1–U6 的最小可执行方案与验收写法

## 0. 结论先行

1. 我支持 S04 §7 的推荐：U1=B、U2 只写雷同度、U3 生产用 HTTP、U4 做最小音频导入、U5 用户安装 ffmpeg、U6 中文走本地导入，不再复述架构。只对 U1 的 B 加一条收窄：**B 只做"用户逐个提供的 URL 单页正文提取"，不做站点检索、不做站内遍历、不做批量爬取**。
2. 真正必须用户点头的是 5 件事：U1 选 A/B、U2 接受"不承诺不侵权"、U3 生产后端与谁付费、U4 接受第 4 步只做导入不做合成、U5 愿意安装 ffmpeg。U6 不需要单独拍板，按"告知 + 安全默认"处理；U7/U8 我无异议。
3. 所有验收都不能依赖中文联网源。P1 的 live 冒烟只做 Gutenberg + 本地中文 txt；中文公版源不可达按 S04 实测记录如实写成"已知限制"，不预先承诺可用。

## 2. U1 来源边界：选 B 的最小形态与边界

### 2.1 三个适配器（P1）

1. `local_import`（默认、必做）：用户把 txt/epub 放进目录或指定路径，`capture import <路径>` 后走同一套解析、评分、选择。零网络、零法律争议，是中文场景的实际主路径。
2. `gutenberg`：gutendex 检索 + epub/txt 下载。只覆盖公版目录，live 冒烟用这一条。
3. `user_url`（仅当用户选 B）：用户提供**单个 URL** → 通用正文提取。约束全部写死：
   - 每次一个 URL；`--urls-file` 为逐条处理的列表，不做站内链接发现；
   - 只用普通 HTTP GET，不提交登录态/cookie，不模拟点击，不绕 401/403/付费墙/验证码/DRM；
   - 遵守 robots，被禁止即失败并记录 `robots_decision`；
   - 不按站点写适配器、不做站点检索；
   - provenance 必填：`url`、`fetched_at`、`http_status`、`robots_decision`、`license="user-asserted"`、`user_ack_at`；
   - UI/CLI 必须显式确认"我确认对该 URL 内容有使用权，并自担来源合规责任"，确认记录进 manifest；
   - 确认缺失 → 拒绝运行，不是警告。

`sources.yaml` 只登记这三个 `source_id`，启动时做白名单校验；新增站点适配器必须改代码并评审，不能靠配置偷偷加。

### 2.2 用户选 A 或 C 时

- 选 A：删掉 `user_url`，只留本地导入 + Gutenberg；README 明示"联网捕获仅限公版目录"；验收不含任何中文联网样例。
- 选 C（任意小说站检索/批量抓取）：当前方案不实现。若用户坚持，来源模型、ToS 审查、限速反爬、验收口径都要重做，需另开方案并由用户书面确认风险。我不建议。

### 2.3 U1 验收怎么写

- 离线：`sources.yaml` 只含 3 个白名单 `source_id`；试图注册未登记来源 → 启动失败。
- 离线：robots 禁止路径 fixture → 拒绝并写 `robots_decision`；403 fixture → 失败且**不重试绕过**。
- 离线：provenance 缺任一必填字段 → schema 校验失败；未勾选用户确认 → `user_url` 拒绝运行。
- 离线：同一本书两份 txt（一完整、一截断/乱码）→ 评分选中完整版，`selection.json` 留痕。
- live 手动：Gutenberg 检索并下载 1 本，命令与输出贴进 handoff；标注"live 手动"，不计入自动通过数。
- **不写**"能够从任意网站捕获中文小说"；只写"在合法源与用户授权 URL 内捕获"。

## 3. U6 中文公版源不可达时的路径

事实依据：S04 实测 `zh.wikisource.org` 两次失败（TLS 超时 / WinError 10054），S04 已声明不外推为永久不可用。我按"本机当前不可达"处理，不重复测试。

路径优先级：

1. **本地导入（一等公民）**：中文书的验收样例用本地构造的 30 章样例 + 用户自有真实 txt；从 import 起全链路可跑。这是能 100% 验收的路径。
2. **用户可访问的 URL**（仅当 U1=B）：用户自己的镜像、代理或授权站点，逐个 URL 提取；项目不内置代理、不改 hosts、不绕网络限制。
3. **Wikisource 适配器**：P2 以后可选。触发条件 = 用户提供一个本机可达的 API base URL 并确认 ToS；届时单列任务与验收，不预先承诺。

是否必须问用户：**不需要单独决策**。按"已知限制 + 默认走本地导入"告知即可；只有用户把"中文联网捕获"写成 P1 硬验收标准时，才必须回来问（给可达源，或改验收）。

验收写法：

- P1 所有中文用例离线；中文样例来自本地 import。
- README 设"已知限制"一节：写明实测时间、失败类型、当前替代路径；不含"以后一定支持"的承诺。
- 若用户后续提供可达公版源，补一次 live 冒烟并记录；在此之前，任何文档不得写"支持中文维基文库"。

## 4. U2 版权风险表述

必须用户确认一次：**验收只写"雷同度低于阈值"，不写"不侵权"**。

固定文案（README、UI 第 3 步、方案验收三处使用同一句）：

> 本工具只做文本改写与相似度检测。相似度低于阈值不代表不侵权；解说、演绎可能构成改编，使用他人作品前请自行取得授权。

验收写法：

- 文案存在性测试：README、UI 常量、方案文本三处字符串一致（可做快照/常量测试）。
- `script` manifest 必填 `source_license` 与三项相似度指标（8-gram 本段/全书、整句照抄率、最长连续公共串）。
- 构造"整段照抄原文"的 fixture → 必须 `fail`；"轻度改写"→ `warn` 或 `pass` 按 S03 阈值表；"原创"→ `pass`。
- 若用户要求把"保证不侵权"写成验收项：不接。请总管记录为用户自担风险，方案表述改为"工程只保证可测的雷同度门槛"。

## 5. U3 生产 LLM 后端与费用配置

采纳 S03/S04 的结论：**测试与演示默认 mock，生产默认 HTTP（OpenAI 兼容），CLI 为可选后端**；不采纳 S02 的"CLI 作生产默认"，理由是登录态、配额与输出解析不可控（S03 §2.5 已论证）。

### 5.1 可设的安全默认（不需要用户立即回答）

- P0 冻结 `LLMBackend.complete(messages, params) -> text + usage`，三实现：`mock` / `cli` / `http`。
- 未配置后端 → 第 3 步结构化报错并给出配置示例；**绝不自动调用付费 API**。
- 默认调用上限：全书 brief ≤8 次/本；每段 ≤2 次（首生成 + 1 次重写）；超过即中止并保留已完成产物。
- key 只从环境变量读；`.env` 入 `.gitignore`；manifest 只记 `model`、`prompt_hash`、`input/output_tokens`、`latency`，不记 key。
- 不编造成本数字：界面显示调用次数与 token，由用户按自己供应商单价换算；需要预算时由用户给上限。

### 5.2 必须问用户（可推迟到 P3 开工前，不阻塞 P0–P2）

- 生产用哪家/哪个模型（DeepSeek、通义、OpenAI 兼容自建、Ollama 等）；
- 谁付费、单本预算上限；
- 是否允许真实联网调用（默认只有显式配置后才允许）。

若用户在 P3 前不指定：默认 mock 只能演示，不能产出真实文案；P3 验收里"真实生成"只能算 live 手动冒烟，不算自动通过。

### 5.3 U3 验收怎么写

- mock 端到端（2→3）离线通过，manifest 记录 `backend=mock`。
- http 后端对本地 stub server 测：请求构造（base_url/model/headers）、超时、重试、非 2xx 结构化错误。
- 超 `max_llm_calls` → 非零退出 + `status=failed` + 已完成产物保留。
- 无 key / 无 base_url → 报错信息包含配置项名称与示例，不抛裸栈。
- 真实调用仅手动 1 段，贴命令、输出摘要、token 数；不计入自动通过。

## 6. U4 第 4 步最小音频导入

这是范围变化，**必须用户确认一次**：本期第 4 步只做"外部音频导入 + 时长探测 + manifest"，**不做 TTS 合成**。理由 S03 §3.1 已给：否则 2→3→4→5 串联与第 5 步验收断链。

最小方案：

- `voiceover import --file <mp3|wav|m4a>` / `--files` / `--dir`；
- ffprobe 取 `duration/channels/sample_rate`，算 sha256；
- 写 `kind=audio` manifest，`producer=external_import`；
- `voiceover synth` 明确返回"未实现"，非零退出，**不产生假音频**；
- UI 第 4 步：上传/选择 → 显示时长 → 交给第 5 步；pipeline 2→3→4→5 用导入音频跑通。

验收怎么写：

- mp3/wav/m4a 各 1 个 → manifest 字段完整，`duration` 与 ffprobe 一致（同源，误差按 0 计）。
- 损坏/伪装扩展名文件 → `status=failed` + 可读原因，不落半成品。
- ffprobe 缺失 → 结构化错误 + 安装提示。
- `synth` → 非零退出，输出目录不新增音频文件。
- pipeline 能消费导入音频并传给第 5 步。

若用户拒绝（坚持纯占位）：E2E 改为 2→3→5，由用户在 UI 上传音频；pipeline 四步链延期，验收相应删减，不能假装跑通。

## 7. U5 ffmpeg 安装门槛

**必须用户执行/确认**：安装系统 ffmpeg（`winget install Gyan.FFmpeg`，或 scoop），装完把 `ffmpeg -version` 输出交给总管；或在 config 指定 `ffmpeg_path`。

- 不打包二进制、不自动下载、不静默回退 `imageio-ffmpeg`；若用户坚持免安装，单独评估并批准。
- `doctor/preflight` 检查：ffmpeg/ffprobe 存在、版本、libx264/aac 编码器、可写临时目录、控制台 UTF-8；第 5 步启动即门禁。

验收怎么写：

- P0 交付 doctor 实际输出；缺失时给出安装命令，退出码可区分"未安装/版本不符/缺编码器"。
- 用户装好后：ffmpeg 自造 fixture（`testsrc2` + `sine`）跑视频与图片两模式；ffprobe 断言时长误差 ≤0.5s、含音视频流、分辨率/帧率符合参数。
- 未安装期间：相关自动测试 `skip`；handoff 与验收记录写"未验证"；P4/P5 不得整体标 pass。
- 不用版权素材做 fixture。

## 8. U7/U8 与已收敛默认值

U7 视频参数、U8 英文目录 + 中文显示名：我支持 S04 的默认值，无需用户拍板，写进方案默认值表即可（全部可覆盖）。第 1 轮已收敛的默认值（A 策略：舍弃章顺延；1/3 严格大于；相似度 3%/5%/整句 10%/LCS 32；`no_future`；300s、4.5 字/秒；`video_tail`；图片余数补最后一张；artifact 带 params_hash）不再重开。

## 9. 给总管的建议

- 用户确认清单建议一次列全 5 项，但标注阻塞关系：**U1、U2 阻塞 P0 契约定稿；U3 阻塞 P3 真实生成；U4 阻塞 P4 链路；U5 阻塞 P4/P5 验收**。这样用户知道哪些现在必须答、哪些可以稍后。
- 方案的"验收标准"可直接采用 §2.3、§4、§5.3、§6、§7 的条文；中文相关一律写"本地导入"，live 只写 Gutenberg。
- 若用户对 U1 选 A：删 `user_url`，需求 1 的"网上捕获"限定为公版目录并写进 README；其余模块和阶段不变。
- 不建议在用户回答前提交 plan v1；这 5 项都会直接改变验收条文，先问后写比驳回重来便宜。
