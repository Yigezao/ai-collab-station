# S03 第 1 轮发言：需求 3 文案可控性、需求 5 视频链路与最小验收

## 0. 结论先行

1. 方向赞同 S01/S02：合法来源硬约束、契约优先、pipeline 串联下沉、两级身份、preflight 先行。需求 3/5 上没有方向性反对。
2. 但三处口径必须在方案定稿前改，否则交付物名不副实：
   - **"不侵权"不能写成可自动验收的属性**。工程能保证的是"与原文不逐字/近似雷同的可测指标"；必须由用户确认这就是验收标准，并在 README/UI 明示边界。
   - **相似度单阈值（LCS≤20 / 8-gram≤5%）会把合理的短引用和常见表达误杀**，应改为"硬失败 + 警告带 + 重写"三级，并把归一化与阈值 fixture 化。
   - **第 4 步不能是纯占位**：至少要实现"外部音频导入 + 时长探测 + manifest"，否则需求 5 的端到端链路和"串联 2→3→4→5"在 P4 无法验收，也接不上用户"最终得到多段音频"的串联要求。
3. 需求 5 的最小可验收范围建议收敛为：**ffmpeg/ffprobe 子进程 + 两种模式（视频+音频、图片+音频）+ 显式裁剪策略 + ffprobe 自检**；转场、字幕、慢推镜头、BGM、平台预设全部二期。ffmpeg 当前不在 PATH（本轮复核 `where ffmpeg` 退出码 1，工作区为空），必须先安装并留 preflight 输出。

## 1. 对 S01/S02 的赞同项（记录共识，避免重复讨论）

1. 相似度不能只看"文件存在"，必须有可复现指标（S01 §3.3，S02 §6.1）。

6. 路径含中文与 `#`，subprocess 一律列表参数、不经 shell（S02 §7/§8）。

## 2. 需求 3：文案生成

### 2.1 "不能与原文完全一样，否则有侵权风险"的正确表达（需用户确认）

用户原话是风险提示，不是法律结论。方案必须分两层写：

- **工程承诺（可验收）**：生成文案与所依据原文的字面重合度低于指定门槛，不复制原文成段内容。
- **不能承诺**：改写就不侵权。解说/演绎本身可能构成改编，取决于用户对文本是否享有权利。

落地：
- README 与 UI 第 3 步固定一句边界说明；script manifest 记录 `source_license` 与相似度指标。
- 方案里的验收标准写"雷同度门槛"，**不要写"无侵权"**。请总管把这条列入方案的用户确认清单（下文 D-Copyright），而不是只在 README 里自说自话。

### 2.2 相似度指标：一个硬门槛 + 一个警告带，并修口径

对 S01/S02 的具体修正：

- **LCS 单值不足以表达风险**：会被专名、成语、套话拉高；真正的风险是"连续复制多少字"。保留 `longest_common_run`，但默认硬阈值从 20 放宽到 **32**（可配 24–40）：解说里点名引用一句原文是常见且合理的，连续 ≥32 字完全一致几乎只能是搬运。
- **主指标用 8-gram 覆盖率**，口径按 S02 的集合去重定义，但分别对**本段原文**与**全书原文**各报一次；默认硬阈值 **≤3%（本段）/ ≤5%（全书）**，警告带为硬阈值的 1.5 倍。
- **新增"整句照抄率"**（与原文完全相同的句子字数 / 文案总字数，句子按句末标点切），默认 ≤10%。这个指标用户看得懂，比 n-gram 更可解释。
- 判定三态：`pass`（全部低于硬阈值）/ `warn`（落在警告带，交付但标黄）/ `fail`（超硬阈值 → 自动重写一次 → 仍 fail 标 `needs_review`，**不得显示为成功**）。两次指标与超标定位（句子 + 片段 + 长度）写入 manifest。
- 阈值必须用三类 fixture 锁定（照抄 / 轻度改写 / 原创），并配归一化单测。注意：**阈值是产品参数，不是法律标准**，README 要这么写。

### 2.3 可控性：把参数和提示词契约结构化

需求说文案"能导入剪辑软件用于生成配音"，隐含时长、风格、断句都要可控。建议第 3 步 CLI 参数/配置：

- `--target-seconds`（默认 300，按 4.5 字/秒反推目标字数，允许 ±15%）
- `--style`（平实/悬疑/爽文/温情等枚举 + 自由描述；枚举写进 prompt 模板，避免每次临时发挥）
- `--perspective`（第三人称/第一人称）、`--persona`（"说书人"口吻可选）
- `--spoiler-policy`（默认 `no_future`：只用本段及之前的信息；`allow` 才允许参考后文）——这是"不脱离长篇背景"与"不剧透"的冲突点，必须显式化
- `--hook`（开头钩子开关）、`--cliffhanger`（段尾悬念开关）
- `--rewrite-on-fail`（默认 1 次）、`--max-llm-calls`（成本硬上限，超限报错，不继续烧）

所有参数、`prompt_version` 写进 script manifest，重跑可追溯（模型随机性除外）。prompt 模板要有 golden 渲染测试。

### 2.4 "不脱离长篇背景"：可自动检查的部分与不可自动检查的部分

S01 的 book_brief + story_state 方向对，但补三点：

- **story_state 必须有 schema**（不是自由文本）：`characters[]`（名字、别名、身份、当前状态）、`plot_progress`、`open_threads[]`、`relationships[]`、`updated_through_chapter`。每段生成后由模型输出 JSON，`common/manifest.py` 校验；失败则保留旧状态并告警。
- **实体白名单校验**：文案中出现的人名/地名应来自 `book_brief.characters` 或本段原文；出现未知专名 → `warn` 并列出。这是低成本发现"编造人物"的唯一自动手段。
- **连续性无法全自动验收**：只能保证 prompt 确实注入了 brief/state（渲染快照测试）+ 抽样人工审查 1 段。方案里不要写成"自动保证不脱离背景"。
- 全书 brief 用 map-reduce，缓存键 = `variant sha256 + prompt_version`；换版本后自动失效。预算进配置（默认 ≤8 次调用/本，可配）。

### 2.5 LLM 后端与测试策略（D3/D14 落地）

- 接口 `LLMBackend.complete(messages, params) -> text + usage`；三种实现：
  1. `mock`：读 fixture JSONL，**测试与离线演示默认**；
  2. `cli`：调本机 `claude -p` / `codex exec`（S02 建议），零 key，但输出解析不稳、依赖登录态与配额，只做可选后端；
  3. `http`：OpenAI 兼容（`base_url`/`model`/`api_key_env`），兼容 DeepSeek、通义、本地 Ollama 等——**建议作为生产默认形态**，可控、可计费、可替换。
- 我不建议把 `cli` 设为生产默认：它让"能不能用"取决于用户是否登录了某个客户端，并发/重试语义也不可控。建议配置中测试默认 `mock`，生产由用户选 `http` 或 `cli`；未配置时第 3 步给出明确提示，不静默失败。
- key 只从环境变量读；`.env` 入 `.gitignore`；manifest 只记 model 名与 `prompt_hash`，**不记 key**。
- 测试：单测全走 mock；HTTP 后端用本地 stub server 测请求构造与错误重试；真实调用只做手动 smoke，结果贴 handoff，不伪装成自动化测试。
- 记录 `input_tokens/output_tokens/latency` 到 run 日志，便于用户评估成本。

### 2.6 文案形态（TTS 友好）

- `script.md`（分段正文）+ `script_lines.txt`（一句一行，UTF-8 无 BOM）。
- 断句规则写死并测试：句末标点切；>40 字的句子在分号/逗号处二次切；仍超长才硬切，且不切断数字/人名。
- 数字、英文缩写、多音字读音无法由纯文本保证，属 TTS 侧差异；`pronunciation_map.yaml` 列二期。
- 每行前不加序号/停顿标记，保持可直接粘贴；SRT/剪映草稿维持二期（同意 S01 D9）。
- `estimated_seconds` 写入 manifest，作为第 4 步未实现时唯一可核对的时长口径（同意 S02 §6.3）。

## 3. 需求 5 与需求 4 的衔接

### 3.1 第 4 步：不是纯占位，最小实现"外部音频导入"

理由：
- 用户明确第 4 步先不写、剪辑软件已有配音；但串联与第 5 步验收必须有音频产物。
- 只建空文件夹 + 抛"未实现"，UI 第 4 步就是死路，pipeline 2→3→4→5 无法无头验收。

建议第 4 步最小功能（约一个 CLI）：

- `voiceover import --file <mp3|wav|m4a> --out <audio_artifact>`：校验存在与可探测、ffprobe 取时长/声道/采样率、算 sha256、写 `kind=audio` manifest（`producer=external_import`）。
- 多段导入：`--files` 或目录 + 命名匹配。
- `voiceover synth` 保持未实现：明确返回"未实现"（非零退出码 + 可读提示），不产生假音频。

这条改动很小，但让"需求 4 占位"与"链路可验收"同时成立。请总管确认纳入 P4（或 P3 末尾）。

### 3.2 ffmpeg：同意 preflight，补三条硬约束

- 我复核：`where ffmpeg` 无结果（与 S02 一致），工作区当前为空。
- `doctor` 检查：ffmpeg/ffprobe 存在与版本、libx264/aac 编码器可用（`ffmpeg -encoders`）、可写临时目录、控制台 UTF-8、目标目录可写。缺任一 → 第 5 步返回结构化错误码与安装命令（`winget install Gyan.FFmpeg` / scoop），**不抛栈、不自动下载**。
- 允许 `ffmpeg_path` 配置覆盖 PATH；版本写入每个 video manifest。
- 不打包二进制（同意 S02 的 GPL 顾虑）。若用户机器实在装不上，再单独讨论 `imageio-ffmpeg` 等方案，需用户批准。

### 3.3 最小可验收范围（建议写进方案 P4）

必须有（MVP）：

1. 视频 + 外部音频 → MP4：目标分辨率/帧率，H.264 + AAC，时长按策略裁齐。
2. 图片 N 张 + 音频 → MP4：每张 = 音频时长 / N，余数给最后一张；统一缩放+裁剪（`scale=...:force_original_aspect_ratio=increase,crop=...`）。
3. 裁剪策略显式化：`--trim-policy {video_tail,audio_tail,video_head,audio_head}`，默认 `video_tail`；长度差 ≤0.5s 不裁。manifest 记录原始/最终时长与裁剪区间。
4. ffprobe 自检：输出时长误差 ≤0.5s、含 video+audio 流、分辨率/帧率符合参数；不通过 → `status=failed` manifest + 明确原因。
5. 批处理：多个音频 → 多个视频，单个失败不中断其余（默认 `--continue-on-error`，退出码汇总）。
6. 输出命名 `work/segments/<seg_id>/video_<profile>.mp4`，manifest 关联 audio artifact 的 sha。

二期（明确不做）：转场、字幕/卡拉OK、BGM 混音、慢推镜头、封面、平台参数预设、GPU 编码、超分。

### 3.4 视频参数默认值（D8 需用户确认）

- 默认 **1080×1920、30fps、H.264(CRF 20/medium)、AAC 192k、yuv420p、+faststart**（小说解说主流竖屏）。
- 提供 `--resolution 1920x1080` 等覆盖；帧率 25/30/60 可配。
- 帧率/分辨率与目标不一致时一律转码，不 `-c:v copy`（否则参数不可控）。
- 音量统一 loudnorm 归一可作为 P4 可选项，先保证链路通。

### 3.5 素材库

- `data/materials/{video,images}/`，config 可指定多个目录；`material index` 扫描并缓存 ffprobe 元数据（duration/resolution/mtime/hash），UI 只读索引，**不对每个文件每次实时探测**。
- 用户直接把文件丢进文件夹，索引随时重建；删除走 trash（同意 S02 §7）。
- 素材版权由用户自担，README 提示；我们不做素材抓取。

### 3.6 需求 5 的测试策略

- fixture 全部用 ffmpeg 自造，不用任何版权素材：`testsrc2=size=320x240:duration=2:rate=30` + `sine=frequency=440:duration=2`，短时长保证测试快。
- 断言解析 ffprobe JSON，不靠文件大小；覆盖：等长、视频长、音频长、差 <0.5s、缺音轨、损坏文件、无 ffmpeg（mock PATH 为空）。
- 图片模式：Pillow 生成不同宽高比纯色图，断言时长分配与分辨率；余数分配断言到毫秒（允许 ±1 帧）。
- 路径用例：工作区内建含中文与 `#` 的临时目录跑一次（S02 §7 同意）。
- 不在自动测试里调真实抓取或真实 LLM；ffmpeg 未安装时测试 `skip` 并明确写"未验证"，不许把 skip 当通过。

## 5. 对 S01/S02 的具体修正意见（不是反对）

1. S01 §3.3：LCS=20 偏严且单指标不够，见 2.2；"超阈值重写一次"要写清"重写后仍超标 → needs_review，不显示为成功"。
2. S01 §3.3 "LLM 依赖是硬决策"：同意必须定，但工程上可先冻结接口 + mock，不让讨论卡住 P0。
3. S02 §6.2 "默认本地 CLI"：不建议设为生产默认，理由见 2.5；建议 `http` 为生产默认形态、CLI 可选。
4. S02 §8 "图片模式余数补最后一张"：同意，但写明按毫秒计算并对 ±1 帧断言，否则验收会出现 1 帧争议。
5. S02 §9.7 端到端"外部音频"：需要先有第 4 步的 import 能力（3.1），否则这一步没有产物来源。

## 7. 风险（按返工概率）

1. "不侵权"被当成可自动验收属性 → 交付后被质疑。靠 D-Copyright 明确边界。
2. 相似度阈值无 fixture/口径漂移 → 指标失真。靠 2.2 + 测试锁定。
3. LLM 默认后端选错（CLI 依赖登录态/解析） → P3 现场改。靠 2.5。
4. 第 4 步纯占位 → 串联与 P4 验收断链。靠 3.1/D16。
5. ffmpeg 未装或版本不符 → P4 验收阻塞。靠 preflight + 用户确认。
6. 图片时长余数与帧率取整争议 → 验收扯皮。靠毫秒级断言与 fps 对齐。
7. 上下文超限导致 brief/state 截断 → 文案脱离背景。靠分段 map-reduce + token 预算日志。
