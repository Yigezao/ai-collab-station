### Q1 问句正文（可直接粘贴）

> 需求 1 的"网上捕获"按哪种范围交付？
>
> **A. 仅本地导入 + 公版目录**：`capture import` 导入你已有的 txt/epub；联网只访问 Gutenberg（美国公版目录）的检索与下载。不提供任何普通网页抓取。
>
> **B.（推荐）A + 用户提供的单个网页 URL 正文提取**：一次一个 URL，`--urls-file` 逐条独立处理；**单页正文通常只有一章，不保证整本**；**多个 URL 不会自动拼成一本书**（排序、去重、断章续接属新范围，需另行确认）；不做站内链接发现、不做站点检索、不提交登录态、不模拟点击、不绕 401/403/付费墙/验证码/DRM，遵守 robots；使用前必须勾选"我确认对该 URL 内容有使用权，并自担来源合规责任"，记录写入 manifest，未勾选即拒绝运行。
>
> **C. 任意小说站关键词检索 + 批量抓全文**：不建议。来源模型、ToS、限速反爬、验收口径都要重做，需另开方案并由你书面确认风险。
>
> 与这题一起成立的事实（2026-10-23 本机一次性核验，不外推为永久结论）：
> 1. Gutenberg 中文公版目录可达（查询返回 444 种），公版古典中文可合法联网获取；但**关键词检索只在 Gutenberg 目录内生效**，简体书名实测 0 条，需用繁体书名或作者名（本期不加繁简转换依赖）。
> 2. **本期未确认任何可接入的、覆盖现代（版权期内）中文长篇小说的授权全文来源。这不等于不存在**：公版（作者逝世超过保护期）、作者/权利人明示授权、开放许可（CC BY/CC0 等）路径均需逐源核验。现代中文小说的实际路径是本地 txt/epub 导入。
> 3. 若你手上有可访问的授权来源或镜像，请给出，按其条款单列任务接入，不占本期默认范围。

### Q2 问句正文

> 验收只写"**雷同度低于阈值**"，不写"不侵权"。固定句（README、UI 第 3 步、`script.md` 末尾、方案验收四处同一句）：
> 「本工具只做文本改写与相似度检测。相似度低于阈值不代表不侵权；解说、演绎可能构成改编，使用他人作品前请自行取得授权。」
> 是否接受？（若要求把"保证不侵权"写成验收项，我们不接，只能改为"工程只保证可测的雷同度门槛"。）

### Q3 问句正文

> 第 3 步（文案生成）本期用哪种后端？三选一：
> 1. **HTTP（OpenAI 兼容）**：请给出 `base_url`/厂商/模型、谁付费、单本预算；只有显式配置后才允许联网，绝不自动调用付费 API。
> 2. **本地 CLI（experimental）**：仅手动运行；manifest 记 `backend=cli, experimental=true`；**不作为生产后端，也不作为任何自动或端到端验收依据**（换机、登录态、配额、输出解析都不保证）。
> 3. **仅 mock**：本期不产真实文案，方案会写明"未交付真实生成"，不算未完成，也不得声称已交付。
>
> 同时请确认预算口径（默认：按次数/token 计）：
> - `logical_calls`（首生成/重写/brief 子调用各 1 次，沿用 brief ≤8 次/本、每段 ≤2 次）与 `request_attempts`（实际发出的 HTTP 请求，含超时/5xx/429 重发）**两个上限同时生效**，任一超限即非零退出、`status=failed`、保留已完成产物，断点续跑不清零；
> - 默认 `max_request_attempts = 逻辑上限 × 3`；最多 2 次重试（共 3 次尝试），4xx（429 除外）与 robots 拒绝不重试；
> - **若要按金额设上限，需同时提供输入/输出单价**；否则系统只按次数与 token 上限执行，界面不显示金额，也不承诺费用不超支。

### Q4 问句正文

> 第 4 步（配音）本期只做「外部音频导入 + 时长探测 + manifest」，**不做 TTS 合成**（`voiceover synth` 明确返回未实现、非零退出、不产假音频）；且它是**人工输入节点，不是自动段**：2→3 自动，第 4 步暂停等你提供音频，4→5 自动。第 3 步产出 M 段文案就需要 M 个音频，**数量不符即 `needs_review`/失败，不会静默取第一个**。是否接受？（不接受则 E2E 改为 2→3→5，四步链延期，验收相应删减，不假装跑通。）

### Q5 问句正文

> 是否愿意在本机安装系统 ffmpeg？项目**不打包、不自动下载、不静默回退**。三条任选：`winget install Gyan.FFmpeg` / `scoop install ffmpeg` / 手动解压 zip 后在 config 填 `ffmpeg_path`（仍需含 libx264 与 aac）。装好后把 `ffmpeg -version` 输出交给总管。
> 影响：ffprobe 随 ffmpeg 提供，未安装时 **U4 的 mp3/m4a 时长项无法验收**（wav 可用标准库 `wave` 验时长；mp3/m4a 标 `duration_unverified`，skip 不算通过），P4/P5 也不得整体标 pass。

## 5. 总管写 decision / 问句前要处理的 4 处

1. **S02 §9 第 1 条的问句措辞与异议 A 冲突**：原文"现代中文小说都没有合法联网源"会被用户读成穷尽核验结论。**必须替换成 §2 的事实 2 原句**（未确认 + 不等于不存在 + 逐源核验路径）。这是本轮最容易漏的一处。
2. **预算口径缺口（S01/S03 都没闭合）**：协议要"预算上限"，但系统供应商中立、不内置单价，**只靠次数与 token 无法证明"费用不超支"**。我的默认：预算 = `max_logical_calls` + `max_request_attempts`（+ 可选 `max_tokens`）；金额上限仅在用户提供单价时按 usage 估算并写 `cost_estimate`，同时明示"估算、非硬保证"。这条要作为 Q3 的组成部分问，否则用户会以为填了预算就绝不会超支。
3. **中文 fixture 来源口径统一**：S01 §3 写"中文用例只能来自本地 import"，S02 §1/S03 §2 已修正为"Gutenberg 中文公版可作真实 fixture"。定稿 = 自动测试 fixture 用**Gutenberg 公版裁剪片段（保留许可头与出处）+ 自造 30 章样例**双轨；live 中文冒烟 1 本、手动。方案不得沿用 S01 旧句。
4. **补一条 P1 验收（内部决定，不需用户拍板）**：S02 §2.3 的 work 绑定——`import` 与 `user_url` 接受显式 `--work/--author`，缺省按页面 title 推断并标 `work_binding=inferred`，**合并前必须用户确认**；验收：同一 work 的 3 个 URL → 3 个 variant 且 `selection.json` 排序正确，不同 work 不得误合并。漏了它，需求 1 的"多版本校验对比"在 URL 路径上无法验收。
