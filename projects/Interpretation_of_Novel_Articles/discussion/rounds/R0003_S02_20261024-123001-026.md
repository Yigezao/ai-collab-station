# S02 评审与独立方案：UI v2（浏览选择 / 操作即选择 / 产出与检索透明）

## 0. 结论与投票

**投票：A**（全盘只读浏览 + 结构化字段 + specs 单一数据源）。

但我对 S01 提案有三处实质修正，建议在 v2 方案里写死：

1. **第 4 步必须补“绑定表格”，不能只让用户手写 bindings.json**（否则“尽量不写代码”在第 4 步直接破功）。
2. **页面建议拆成 3 个静态文件**（与 S01 §8 相反）；若坚持单文件，至少把 `str.format` 换成 token 替换。
3. **产物路径必须标注来源**：有的来自模块 JSON，有的是按库布局推导（compare_work 不返回 comparison.json 路径），不能一律说“从模块 JSON 提取”。

其余（A 选型、不做 B/C、不重算 hash 目录、CSRF/环回加固、不改模块 CLI 契约、零新依赖）我同意。

## 1. 逐条回应 S01 的 5 个问题

### 1.1 选型 A 是否足够，是否需要 B（上传复制）补充？

**A 足够，v2 不引入 B，也不引入 C。**

- B 的真实代价不只是磁盘：浏览器 `<input type=file>` 上传后服务端只能保存为 `data/uploads/<随机名>`，`source.cli import` 的 `source_id` 会退化成 `local:<上传文件名>`，`provenance` 里的原始绝对路径丢失；而 import 本身已经把原文件复制进 `variants/<vid>/source/`，等于同一份文件存两遍（用户副本 + 库副本），来源追溯反而变差。
- B 还要处理大文件分片、体积上限、失败清理、同名冲突，属于新增代码面；对“直接浏览选择”这个明确诉求没有增益——用户要的是“看见文件、点它”，不是“先把文件搬到项目里”。
- 唯一可能受益的场景是“浏览器在另一台机器”，但这违反本项目“只绑 127.0.0.1”的不变量，直接排除。
- C（桌面对话框）继续不引入：服务线程弹 tkinter 会卡、无桌面环境不可用、无法自动测试，收益与 A 完全重叠。

结论：B 不做主路径、不做补充；如果以后用户明确要“拖拽上传”，再单独立项，且必须把 `source_id` 与原始文件名写进 provenance，不能悄悄复制。

### 1.2 浏览边界：全盘只读还是白名单？

**推荐全盘只读浏览，不做白名单**，但必须满足下面 6 条硬约束（缺一条我就反对）：

1. 只返回目录项元数据（name/path/kind/size/mtime/hidden），**永不返回文件内容**；单层列出、不递归、单层上限 2000 条。
2. 路径必须绝对；`normpath` 后必须存在；拒绝相对路径、空串、NUL 与控制字符、`~` 未展开；返回结构化错误码（`INVALID_INPUT` / `NOT_FOUND` / `NOT_A_DIRECTORY` / `PERMISSION_DENIED`），不静默回退到 cwd。
3. 绑定 127.0.0.1（不变）+ 校验 Host（带端口，仅 `127.0.0.1` / `localhost`）+ 所有 POST 必须 `Content-Type: application/json` 且带自定义头 `X-UI-Request: 1` + 不返回 CORS 头；请求若带 `Origin`，必须是 `http://127.0.0.1:<port>` 或 `http://localhost:<port>`，否则 403。
4. 默认隐藏 Windows hidden 属性与点文件（`AppData` 之类），页面提供“显示隐藏项”开关。
5. 提供快捷入口：盘符根、用户主目录、桌面、下载、项目根、`data/library`、最近使用（从 `/api/works` 推导）；否则从盘符一路点下去同样是折磨。
6. 列出 junction/符号链接时只作为条目返回，不自动展开目标；不因单个条目 stat 失败而让整个列表失败（跳过并在 `warnings` 里说明）。

为什么不做白名单：

- 用户的稿件通常在桌面/下载/D 盘，白名单要么默认覆盖全盘（等于没限制），要么每换一个目录就要改配置——改配置就是“写代码”，与用户原话直接冲突。
- 白名单声称的安全收益是“防本机其他页面读取目录名”。这个威胁的实际入口是跨站请求，已被第 3 条（自定义头 + Origin + 无 CORS）覆盖；对“同机同用户的其它进程”，白名单也挡不住（它们本来就能直接读盘）。
- 剩余风险如实写进 README：**无认证的环回服务，任何本机进程都可调用**；如果要更严，后续可加“启动时生成随机 token 写进 URL、API 校验 token”，但不应阻塞 v2。

### 1.3 默认 hash 目录的预览口径是否可接受？

**方向可接受（不重算 hash），但 S01 的表述不够，需要补 4 条：**

1. **每一步都要能填“自定义输出目录”**：一旦显式给了绝对路径，预览就是精确的；默认 auto 时才显示“父目录 + 命名规则 + 运行后确定”。这样想精确预览的用户有路可走，不想管的用户也不用手填。
2. **覆盖保护不能只靠 UI**：真正的硬闸门是模块自身“目标已存在/非空默认拒绝，需 `--force`”。UI 预览发现冲突时只负责显示红色提示并要求勾选确认；**永远不自动加 `--force`**，未勾选时服务端拒绝。
3. **运行后必须回填实际路径**：把模块 JSON 里的真实路径写进“本次运行记录”，并据此预填下一步；不能要求用户运行完再去 JSON 里找。
4. **预览要按操作区分**，不能只按步骤：
   - 可精确：`variants` → `<library>/<work_id>/comparison.json`、`select` → 模块返回的 `selection`、`parse` → `chapters_file`、第 2 步显式 `--output-dir`、第 3 步显式 `--out`、第 4/5 步 `out`（必填）。
   - 不可精确：`import`/`download` 的 `variant_id` 依赖内容摘要，第 2 步默认 `segments/run-<params_hash>`（hash 含输入摘要与章节文件），第 3 步默认 `script/run-<params_hash>`。这些只显示父目录 + 规则 + “运行后确定”，并明确写出“UI 不复制模块的 hash 逻辑”。

### 1.4 五步免手填测试的最小 fixture 集

**全部运行时生成，不提交二进制 fixture**；用临时库目录，绝不碰用户 `data/library`：

| 步骤 | 最小 fixture | 说明 |
|---|---|---|
| 1 import | 一个 UTF-8 中文 txt，3 章，文件名含中文与空格；`--title` 显式给出 | `title` 决定 `work_id`，必须显式；顺便测中文/空格路径 |
| 2 segment | 用第 1 步产物，`--chapters 1` | 固定章节数切段，避开字数边界规则，得到 3 个 seg |
| 3 script | 用第 2 步 `index`，mock 生成 | 断言 script.md / script_lines.txt / manifest.json 存在 |
| 4 audio | 按第 2 步 `index` 的 seg_id 逐个**用标准库 `wave` 生成 8kHz/单声道/16bit/0.2s 静音 wav**，用重复 `--binding seg_id=path` 传入 | 不提交音频文件；wav 时长由标准库探测，全部 verified；同时验证“绑定表格 → argv” |
| 5 video | images 模式 + 1 张 1×1 PNG（测试里用 base64 常量写临时文件）；**无 ffmpeg 时断言退出码 3 / `DEPENDENCY_MISSING` 且 UI 不判 done**；有 ffmpeg 时才跑真实渲染并断言 `final.mp4` | 不宣称“本机已验证真实编码”，测试里按 `shutil.which` 分支并写明原因 |

**不需要**：epub（已有单元测试）、mp3/m4a（需要 ffprobe）、真实网络 search（用 mock client 测）、长音频、视频素材。

另外必须断言两件事，否则“免手填”名不副实：① 全程只通过结构化字段构造 argv，页面/请求里没有任何参数串；② 每步产物路径来自模块 JSON（或明确标注的布局推导），且失败/未验证状态不会被显示成 `ok`。

### 1.5 页面是否拆成静态文件？

**建议拆，与 S01 §8 相反。** 理由：

- 页面要装下 spec 渲染、目录浏览弹窗、绑定表格、产物卡片、运行记录，内嵌进 `server.py` 的 Python 字符串后，`HTML_PAGE.format(...)` 要求所有 JS 花括号写成 `{{ }}`，任何一次编辑都可能引入转义错误，且无法被编辑器语法检查覆盖。
- 拆法不引入“静态路由复杂度”：`ui/static/index.html` + `app.js` + `app.css`，server 用**固定映射表**服务（`/static/app.js` → 固定文件），不接受用户传路径，因此没有目录遍历面；`render_page()` 保留，改为读取模板后做 **token 替换**（如 `%%DISCLAIMER%%`、`%%STEP_TITLES%%`），不用 `str.format`，现有 `test_server.py` 对 `render_page()` 的断言继续有效。
- 代价：+3 个文件、1 个固定路由；文件缺失时显式报错（500 + 明确 message），不要返回空白页；测试补一条“静态文件存在且能被服务”。
- 若团队最终坚持单文件，我接受但要求：改用 token 替换而不是 `str.format`，并把页面复杂度控制在可审查范围；这一点我会在评审时复检。

## 2. 独立方案：接口与字段

### 2.1 目录/文件浏览接口（`ui/fsbrowse.py` 纯函数 + server 路由）

- `GET /api/fs/roots` → 盘符（`os.listdrives()`，3.12+；否则 A–Z `exists()` 探测，结果缓存 30s）+ 快捷入口 + 默认库绝对路径。
- `GET /api/fs/list?path=<绝对路径>&kind=dir|file|both&accept=.txt,.epub&show_hidden=0`
  - 返回：`cwd`（resolve 后绝对路径）、`parent`、`exists`、`is_dir`、`writable`、`truncated`、`warnings`、`entries[]`；
  - `entries[]`：`name`、`path`（绝对）、`kind`、`size`、`mtime`、`hidden`、`ext`；目录在前，按名称排序；`accept` 只用于前端灰显，不在后端偷偷过滤（否则用户以为文件不存在）。
- `POST /api/fs/mkdir {parent, name}`：只建一层；`name` 不得含路径分隔符；父目录必须存在且可写；已存在返回 `INVALID_INPUT`；返回新目录绝对路径。只新建，不覆盖、不删除、不改名。
- `POST /api/reveal {path}`：只接受**已存在目录**（文件则打开父目录）；`os.startfile` 失败/无桌面返回 `unsupported`，页面显示路径并提示复制；绝不执行文件、不拼 shell。
- 路径解析统一走 `fsbrowse.resolve()`：展开 `~` → `Path.resolve()` → 校验绝对/存在/类型；任何一步失败返回结构化错误。

### 2.2 操作即选择：`ui/specs.py` 作为唯一数据源

结构建议（字段名可调，语义固定）：

```
STEPS = [
  {step: 1, module: "source", operations: [
     {id, name, summary, fields: [...], artifacts: [...], notes: [...]}, ...]},
  ...
]
FIELD = {key, label, kind, required, default, default_source, choices, accept,
         cli: {mode: "flag|positional|repeat", name}, help, target_next}
```

- `kind`：`text | int | float | bool | choice | file | files | dir | seg_bindings`。
- `default_source`：`constant` / `step_artifact:N` / `library` / `last_run` / `user`；页面据此显示“默认值从哪来”。
- `runner.build_command` 改为**spec 驱动**：按字段声明的 `cli.mode` 生成 argv（`repeat` 对应 `--path`/`--binding`，`positional` 对应 search 的 queries），仅保留少量特例（第 4 步无绑定返回 `None`、第 2 步 target_chars/chapters 二选一互斥校验）。
- `source_args` 保留兼容但 UI 不再发送；**同时出现结构化字段与 `--source-args` 直接 `INVALID_INPUT`**（同意 S01）。CLI 帮助标注 deprecated，下一版移除。
- 两层校验：前端即时校验（必填/类型/范围）+ 服务端 `StepOptions` 再校验；范围写进 specs（`limit 1..50`、`fps > 0`、`threshold` 留空用模块默认、`target_chars/chapters` 二选一）。

**第 1 步六个操作的字段（精确到 CLI 形态）**

| 操作 | 字段 → argv | 默认 / 说明 |
|---|---|---|
| import | `paths[]` → 重复 `--path`（文件浏览多选，accept `.txt,.epub`）；`title` → `--title`；`author` → `--author`；`work_id` → `--work-id`（可选，下拉已有 work）；`library` → `--library` | `title` 留空时由模块按文件名推断，会改变 work 分组——页面必须提示；每个文件各自成为 variant |
| search | `queries` → **位置参数**（书名，空格分隔多本）；`language` → `--language`；`limit` → `--limit` | language 留空=不过滤；choices 不限/zh/en，可手填其它代码；limit 1..50 默认 5；注明不做繁简转换 |
| download | `gutenberg_id` → `--gutenberg-id`（整数必填，可从搜索结果一键带入）；`title`/`author` → 同名参数（默认取目录标题/作者，可改）；`format` → `--format` auto/epub/txt；`library` | 只从公版目录下载；下载失败按退出码 4 处理 |
| variants | `work_id` → `--work-id`（下拉，必填） | 生成/覆盖 `comparison.json`，只读比较 |
| parse | `work_id` → `--work-id`；`variant_id` → `--variant-id`（随 work 过滤） | 可先提示 `normalized/chapters_override.json` |
| select | `work_id`、`variant_id`、`confirm_binding` → `--confirm-binding` | `confirm_binding` 在 `binding_requires_confirmation=true` 时必须勾选；页面展示当前 binding 状态 |

**第 2–5 步字段（补充 kinds 与说明）**

- 第 2 步：`variant_dir`（dir，必填，上一步带入）或 `work_id`+`variant_id`（二选一，默认用目录）；模式单选“目标字数 / 每段章节数”（互斥，必填其一）；`out`（dir，可空=auto）；`drop_partial`（仅字数模式可用）；`library_dir`（高级）。
- 第 3 步：`segments`（file `.json`，必填）；`threshold`（float，可空=模块默认 0.5，帮助里写明不是法律判断）；`similarity_n`；`out`（可空=auto）；明确 `mock` 徽标与版权提示。
- 第 4 步（**关键补充**）：
  - `seg_bindings`：服务端只读用户选中的 `index.json`，取出 `segments[].seg_id` 列表，页面渲染“段号｜seg_id｜音频文件（浏览选择）”表格；提交时**直接构造重复 `--binding seg_id=绝对路径`**，不写 bindings.json——用户全程不写代码。
  - `bindings`（file，可选，高级替代方式）；`audio_dir`（dir，可选）；`ffprobe`（file，可选）；`out`（dir，必填）。
  - 若 index.json 无法读取（格式/权限），退回仅文件方式并明确提示，不猜。
  - “读 index.json”只用于列出 seg_id，不重写模块校验；段数不一致、重复、多余仍由模块拒绝。
- 第 5 步：`audio_manifest`（file `.json`，必填，上一步带入）；`mode` 单选 video/images（切换时只显示对应字段）；`materials_dir`/`images_dir`（dir）；`duration_strategy` 选项必须带中文说明（trim_video=裁视频到音频长度 / trim_audio=裁音频到素材长度 / pad_silence=补静音 / in_out=手工指定入出点），`in_point`/`out_point` 仅在 in_out 时显示；`resolution`/`fps`（可空=模块默认）；`ffmpeg`/`ffprobe`（file）；`out`（dir，必填，必须为空或不存在）。

**页面结构（每步三块）**：操作选择卡片（选中后显示“做什么 / 必填与可选 / 默认值来源 / 会写到哪里 / 常见失败码”）→ 输入区（每个路径字段都有“浏览选择”+“手动输入”，选择后显示绝对路径）→ 产出区（预览 / 运行结果 / 实际产物卡片 / 下一步预填按钮）。

| parse | `chapters_file` | |

### 2.4 检索口径与状态说明（页面常驻，值来自配置而非复制）

- 从 `common/config.py` 读取并展示：`gutenberg_api`、`timeout_seconds`、`request_interval_seconds`、`max_attempts`；避免页面写死一份与配置漂移的说明。
- 写清楚：`q=书名`（空格分隔多本，逐本请求）、`languages=语言代码`、`limit=每本返回条数`；返回字段表；空结果说明（只查公版目录，简体书名可能 0 条，实测“红楼梦”0 条/“紅樓夢”有结果；不转繁简、不代理、不缓存）。
- 退出码常驻表：0 ok；2 输入/产物错误；3 依赖缺失；4 访问/网络/robots/TLS；5 需人工复核；6 未实现；7 内部错误；每个操作标注常见失败码。
- preflight 面板：Python 版本、库根是否可写、ffmpeg/ffprobe（`shutil.which` 或用户填写路径）、项目根、当前库绝对路径。

### 2.5 运行与并发

- 服务端同一时刻只允许一个模块子进程运行（模块内 `threading.Lock`），并发请求返回 `BUSY`，避免两个请求同时写同一输出目录；页面按钮在运行中禁用。
- 保留 300s/600s 超时，超时映射为 `failed` 并说明“模块执行超时”。
- 路径统一在 UI 侧 `resolve()` 成绝对路径再传给模块，预览显示的路径与实际运行完全一致；相对路径按项目根解析并在页面显式显示解析结果。

| # | 分歧 | 替代做法 | 代价 | 风险/重评条件 |
|---|---|---|---|---|
| 1 | 页面拆分 | 拆 3 个静态文件 + 固定路由 + token 替换 | +3 文件、1 路由、文件缺失需显式报错 | 低；若团队拒绝，保留单文件但必须改 token 替换 |

| 5 | 库位置 | 页面统一一个“库位置”设置，默认 resolve 成项目根下 `data/library` 的绝对路径，并显示出来；step1 `--library` 与 step2 `--library-dir` 用同一个值 | 需要 specs 把两个参数映射到同一 UI 字段 | 低；否则用户换库后两步不一致，产物“找不到” |
| 6 | `--source-args` 兼容 | 保留但 deprecated，与结构化字段同时出现即拒绝 | 保留一条旧路径 | 低；下一版删除 |

## 4. 用户原话四点覆盖自检

1. **“直接浏览选择文件”** → `/api/fs/roots` + `/api/fs/list`，每步路径字段都有“浏览选择”，返回绝对路径（§2.1）。
2. **“想要什么操作直接选择（给出说明）”** → 操作卡片 + specs 单一数据源，每个操作固定展示做什么、必填/可选、默认值来源、写到哪里、失败码（§2.2）。
3. **“尽量不写代码”** → 第 1 步参数串拆成结构化字段；第 4 步绑定表格直接生成 `--binding`；所有路径浏览选择；高级参数折叠但保留（§2.2）。
4. **“接口都留好，清晰明了。每个产出地址，具体检索什么的都写好”** → `/api/spec`、`/api/fs/*`、`/api/works`、`/api/artifacts`、`/api/preflight`、`/api/preview`、`/api/step`、`/api/reveal`；产物卡片给绝对路径与来源；检索口径常驻并从配置读取（§2.1–§2.4）。
