# UI v2：浏览式选路径、操作即选择、产出与检索口径透明

# S01 提案：UI v2——浏览式选路径、操作即选择、产出与检索口径透明

## 0. 结论先行
选型推荐 A：服务端目录浏览 API。B（上传复制到 data/uploads）不做主路径，v2 不引入；C（系统文件对话框）不引入。理由：A 零第三方依赖、可自动测试、能返回绝对路径，中文/空格/盘符都可控；B 会产生副本，来源追溯变模糊且占磁盘；C 依赖桌面会话与 tkinter，服务线程弹窗易卡死、无头环境不可用、无法自动测试，还增加平台分支。

落地方式：把“步骤 + 操作 + 字段 + 默认值 + 产物 + 说明”抽成单一数据源 ui/specs.py，页面按它渲染；runner 从结构化字段构造 argv，彻底去掉第 1 步参数串；新增只读目录浏览、预检、产物发现与预览接口；不改任何模块 CLI 契约与退出码。

## 1. 架构与改动文件（全部在 UI 层与文档）
新增：
- ui/specs.py：纯数据与纯函数。定义 5 步、每步 operations；每个 operation 含 id、名称、一句话说明、字段列表（key、label、type、required、default、default_source、choices、help、accept）、产物路径规则、示例。字段与 StepOptions 一一对应，测试校验两边不漂移。
- ui/fsbrowse.py：路径安全与浏览纯逻辑。list_dir、list_drives、make_dir、resolve_open_target，不含 HTTP。
- tests/ui/test_specs.py、tests/ui/test_fsbrowse.py。

修改：
- ui/runner.py：StepOptions 增加结构化来源字段（见 §3）；build_command 第 1 步按操作分支构造 argv；source_args 保留但 UI 不再发送，二者同时出现返回 INVALID_INPUT；新增 extract_artifacts(step, payload)，从模块 JSON 提取真实产物绝对路径。
- ui/server.py：新增 §2 接口；页面改为按 /api/spec 渲染表单，加入目录选择器、预检面板、产物卡片与“打开目录”。
- ui/cli.py：同步新增结构化参数，--source-args 保留兼容并标注 deprecated。
- README.md：新增“UI 操作顺序、每步产物绝对地址、检索口径、退出码表”一节。
- tests/ui/test_server.py、test_runner.py 扩展。

不动：source/segmentation/script/audio/video 的代码、CLI 参数、manifest 字段与退出码；不引入第三方依赖（仍只用标准库 + 既有 requests）。

## 2. 新增接口（全部只绑 127.0.0.1，JSON）
- GET /api/spec：返回 5 步与各操作说明，供页面渲染。
- GET /api/fs/list?path=：path 为空时返回盘符与常用位置（项目根、用户主目录、data/library）；有 path 时返回 path、parent、exists、writable、truncated、entries（name、path、kind=dir|file、size、mtime、hidden）。单层最多 2000 条，不递归、不读文件内容。
- POST /api/fs/mkdir {parent,name}：只建一层；父目录必须存在且可写；已存在返回 INVALID_INPUT；不覆盖、不删除、不改名。
- GET /api/works：扫描 library_dir，返回 work_id、title、author、variants（variant_id、variant_dir、chapter_count、source_type、selected、mtime），让第 2/4 步用下拉选择，不必手填 ID。
- GET /api/artifacts?step=N：按 mtime 发现候选输入（segments/run-*/index.json、script/run-*/、audio_manifest.json、素材目录），供 datalist 预填。
- GET /api/preflight：检查 Python 版本、library 根可写、ffmpeg/ffprobe（shutil.which 或用户填写的路径）、项目根，并按步给出依赖结论。
- POST /api/preview {step,options}：不启动子进程，返回 will_write（path、rule、exists、overwrite）、requires_confirm、warnings。显式 out 可给精确绝对路径；hash 默认目录（segments/run-xxxx、script/run-xxxx）只显示父目录与规则，并标注“实际目录运行后显示”，不复制模块的 hash 逻辑。
- POST /api/step {step,options,confirm_overwrite}：在现有结果上增加 artifacts（label、path、kind）与 next_inputs（下一步该填什么）。
- POST /api/reveal {path}：只打开已存在目录（文件则打开其父目录）；os.startfile 不可用时返回 unsupported，页面改为显示并复制路径；绝不执行任意程序。

## 3. 操作即选择：第 1 步结构化字段
每个操作卡片固定展示五件事：做什么、必填/可选、默认值从哪来、会写到哪里、失败时看哪个错误码。其余步骤保留现有字段并补同样的说明。

- import：paths[]（文件浏览多选，accept .txt、.epub）、title、author、work_id（可选，下拉）、library（可选，默认 data/library）
- search：queries（书名，空格分隔多本，逐本查询）、language（留空不过滤；zh/en，可手填其他代码；注明不做繁简转换）、limit（1..50，默认 5）
- download：gutenberg_id（整数，可从 search 结果一键带入）、title、author、format（auto/epub/txt）
- variants：work_id（下拉）
- parse：work_id、variant_id（下拉）
- select：work_id、variant_id、confirm_binding（复选框；WORK_BINDING_UNCONFIRMED 时必选）

StepOptions 新增：import_paths、title、author、work_id、library、queries、language、limit、gutenberg_id、format、confirm_binding。build_command 全程用 argv 列表，中文与空格不经 shell。

## 4. 自动带出（不让用户记 ID/路径）
- 页面加载即调 /api/works 与 /api/artifacts，填充 work/variant 下拉与最近的 index.json、audio_manifest.json 候选。
- 每步成功后服务端返回 next_inputs，前端把 variant_dir 带入第 2 步、index 带入第 3/4 步、第 4 步 out 下的 audio_manifest 带入第 5 步；只填空白字段，并提示“已从第 N 步带入”，用户可改。
- 所有输入框保留“手动输入 / 浏览选择”两种方式，预填不锁定。
- preflight 在第 4 步提示 mp3/m4a 需要 ffprobe，第 5 步提示需要 ffmpeg；缺失时不阻止输入，但标注会返回 DEPENDENCY_MISSING。

## 5. 产出地址与覆盖保护
- 每个输入区上方显示该步“将写入”的规则；执行前点“预览”调用 /api/preview，列出可确定的绝对路径及是否已存在。
- 执行后产物卡片列出模块 JSON 中的真实路径：第 1 步 variant_dir/manifest；第 2 步 output_dir/index；第 3 步 out_dir 与 files.script/files.lines；第 4 步 manifest；第 5 步 output/manifest/timeline。每项带“打开目录”“复制路径”。
- 覆盖保护：预览发现目标非空时 requires_confirm=true；页面显示红色提示并要求勾选“我确认覆盖”；未勾选时 /api/step 拒绝 force=true（服务端校验 confirm_overwrite 必须为 true），禁止静默覆盖。
- 诚实边界：run-xxxx 目录名由模块参数 hash 决定，UI 不重算、不编造，只显示父目录与规则，运行后显示实际值。

## 6. 检索口径与状态说明（页面常驻）
- Gutenberg：接口 https://gutendex.com/books（common/config.py 默认值）；q=书名（空格分隔多本，逐本请求）、languages=语言代码、limit=每本条数；返回 gutenberg_id、title、authors、languages、download_count、formats、ebook_page。
- 空结果说明：只查公版目录，简体书名可能 0 条（实测“红楼梦”0 条、“紅樓夢”有结果），可换繁体书名或作者名；本工具不转换繁简、不代理、不缓存结果。
- 退出码表（来自 common/errors.py，不改）：0 ok；2 输入或产物错误；3 依赖缺失；4 访问/网络/robots/TLS 拒绝；5 需人工复核或人工节点；6 未实现；7 内部错误。每个操作标注常见失败码。
- 每步产物清单表保留并补绝对路径规则。

## 7. 安全边界（本机也必须防误用）
- 只绑 127.0.0.1（不变）；校验 Host 为 127.0.0.1 或 localhost（防 DNS rebinding）；POST 必须 Content-Type: application/json 且带自定义头 X-UI-Request: 1（跨站表单无法带自定义头，配合不返回 CORS 头可挡 CSRF）；响应不加 Access-Control-Allow-Origin。
- 路径必须绝对，拒绝 NUL 与控制字符，resolve 后校验；目录浏览只读、单层、限条数；不返回文件内容；不对 junction 递归。
- mkdir 只建一层且不覆盖；reveal 只接受已存在目录，文件打开父目录；不执行文件。
- 不新增联网（Gutenberg 检索沿用原实现）；站点不存密钥。

## 8. 风险与对策
- 目录浏览扩大本机信息面：loopback + Host 校验 + CSRF 头 + 只读单层；若评审认为仍过宽，可加白名单（项目根、用户主目录、data/library、盘符根）。
- Windows 盘符枚举：优先 os.listdrives()（3.12+），否则 A-Z exists() 探测；盘符根与中文路径必须有测试。
- 默认 hash 目录无法精确预览：已明确只显示规则，避免复制业务逻辑。
- 第 1 步拆字段后旧 --source-args 兼容：两者同时给直接拒绝，防止静默偏离。
- 页面仍是单文件内嵌 JS，复杂度上升但无构建链；本次不拆静态文件，避免引入静态路由。
- 真实 ffmpeg 编码仍未验证，README 已知限制不变，UI 不宣称端到端通过。

## 9. 测试点（可自动验证）
- test_fsbrowse：相对路径、空路径、NUL 拒绝；临时目录含中文与空格名可列出；mkdir 新建/已存在/父不存在/无权限；盘符列表包含 C:\；条目上限截断。
- test_specs：5 步每个操作的字段与 StepOptions 字段一致；必填字段非空；默认值来源有定义；预览规则非空。
- test_runner：六种 source 操作的 argv 正确（含中文与空格路径）；source_args 与结构化字段冲突返回 INVALID_INPUT；confirm_overwrite 缺失时 force 被拒。
- test_server：/api/spec、/api/fs/list、/api/works、/api/artifacts、/api/preflight、/api/preview 正常；缺 CSRF 头或 Host 错误返回 400；非 loopback 拒绝（已有）；/api/reveal 对不存在路径返回 not_found、无桌面返回 unsupported。
- 免手填走完五步：临时 library + txt fixture 依次 import→segment→script→（wav fixture）audio；第 5 步在无 ffmpeg 时断言 DEPENDENCY_MISSING 而非成功；只断言产物路径存在与状态映射，不宣称真实编码通过。

## 10. 不变量
不改各模块 CLI 参数、JSON 字段、manifest 与退出码；第 4 步仍需人工绑定，不自动配音；第 3 步仍为 mock；UI 只转发不重写业务；新增依赖为 0；页面仍只绑环回。

## 11. 请 S02 重点评审
1) 选型 A 是否足够，是否需要 B 作为“外部文件快速复制”补充；2) 浏览边界用全盘只读还是白名单；3) 默认 hash 目录的预览口径是否可接受；4) 五步免手填测试的最小 fixture 集；5) 页面是否拆成静态文件。

建议投票选项：A 全盘只读浏览 + 结构化字段 + specs 单一数据源；B 白名单浏览；C 上传复制；D 桌面对话框。
