# 方案 v1：日更书籍解说（10–20 分钟音频稿）方案与模板

> 提交人：MGR。状态：待用户批准。批准前不建任务、不写交付物。
> 依据：REQ-0001、S01 提案（R0001_S01）、S02 评审（R0001_S02）、裁决记录见工作站 `decisions/`。

## 0. 一句话

在项目工作区交付 7 个可直接使用的文件：一套“6 槽位共享骨架 + 文学/叙事双模块包”的单文件提示词模板，用户把模板和素材喂给自己的 AI，就能稳定产出 10–20 分钟音频口播稿、质检和发布件。V1 只交付方案与模板，不做视频、不做真实 TTS 试验、不选真实书目。

## 1. 范围

**做**：
- 可执行的主模板（输入字段、素材闸门、执行协议、输出五块、双模式模块包、钩子 8 型）。
- 字数/时长/槽位预算表、长文本压缩 SOP、质检清单、虚构示例、选题与排期。
- 一个干净的工作区目录：README + 01–06。

**不做**：
- 不做视频/字幕/配图；不做真实书评；不引用任何真实书名、作者生平、引文。
- 不接 TTS 或剪映；不做账号注册、发布、平台运营。
- 只覆盖文学/思想类与叙事/网文类；其它类型只给 `mode_override` 结构建议。

## 2. 冻结参数（实现期间不得改动）

### 2.1 语速与字数

- 单一 `cpm` 字段：文学 **250**、叙事 **290**（均为推定值，不称“实测”；叙事需 TTS 1.05–1.1 倍速，音色变硬降 280）。前 3 期实测后由用户覆盖该字段。
- 字数目标（单点，允许 ±8%；实际时长以 TTS 实测为准，目标 ±1.0 分钟）：

| 目标时长 | 文学 | 叙事 |
|---|---|---|
| 10 分钟 | 2500 | 2900 |
| 15 分钟（默认） | 3750 | 4350 |
| 20 分钟 | 5000 | 5800 |

### 2.2 槽位秒数（S1 钩子 / S2 坐标 / S3 主体一 / S4 主体二 / S5 收束 / S6 固定尾）

| 档位 | S1 | S2 | S3 | S4 | S5 | S6 | 合计 |
|---|---|---|---|---|---|---|---|
| 10 分钟 | 45 | 70 | 145 | 185 | 120 | 35 | 600 |
| 15 分钟 | 50 | 95 | 240 | 285 | 200 | 30 | 900 |
| 20 分钟 | 55 | 105 | 330 | 405 | 275 | 30 | 1200 |

- 钩子固定 45–55 秒，不随档位压缩；S5 占比 ≤23%（20.0% / 22.2% / 22.9%）。
- 分槽字数预算 = 该槽秒数 × cpm ÷ 60，写入 01 与 02，必须与总量一致。
- S6 固定尾内容（签名 + 1 个互动问题 + 1 句预告）不随档位伸缩，字数 105–125（文学）/ 120–145（叙事）。

### 2.3 质检阈值

- 时长：TTS 实测在目标 ±1.0 分钟内；字数在目标 ±8% 内；两者冲突以实测为准。
- 句长：平均 16–26 字；单句 >30 字报错；≥40 字只提示。切句口径：按 。？！… 切分，只数汉字，不含标点、数字、引号内文字。
- 【待核】只允许出现在 S3/S4；S1 与 S5 禁止；发布前清零。
- 节拍：S3/S4 内每 90–150 秒一个新信息或转折；S5 不设小结，改为 2–3 个递进问题；叙事情节点 6–8 个（每个 70–110 秒）。
- 禁用词：两模式各 6–8 条；正文零标记（不得出现 `[停]`、`【重音】` 等）。
- 剧透：默认 `no_ending`；爽点/名场面必须讲；连载中强制 `no_ending` + 进度提示，完结多年可 `main_ending_ok`。
- 版权：书名作者名可用；单处引文 ≤50 字、全文 ≤300 字、标出处（网文标章号）；封面不用原书封面/剧照；连载中作品不做逐章复述；平台要求时标 AI 生成。

### 2.4 模板结构

- 单文件双模式，第 0 块强制输出 `MODE` + 选用参数表（一眼识别串模）。
- 执行协议：第 0 轮只输出 MODE + 参数表 + OUTLINE，等用户回“继续”；每次只写 1–2 段并自报字数（标“估算”）；全文完成后另起一条消息跑 QC；模板自包含，不依赖模型对本书的任何记忆。
- 素材闸门：`author_bio / ending / key_settings / quotes` 任一为空 → 拒绝进入 SCRIPT，只输出“缺哪些素材”。
- 输出五块：`OUTLINE` / `SCRIPT` / `QC`（AI_SELF_CHECK 6 项含证据 + HUMAN_CHECK 5 项）/ `FACT_CHECK` / `PUBLISH`（标题 3 候选、封面大字、简介、标签）。
- 账号标识（3–8 字）固定放 S2 第 8–15 秒；钩子不自我介绍。
- 钩子 8 型（反常识断言 / 具体场景 / 数字对比 / 争议问题 / 一句原文 / 失败结局 / 身份代入 / 时间压力），连续 3 期不用同一型。
- TTS 适配：生僻字注音或换称呼；他/她/它改名字；数字统一读法；英文缩写中文化；括号斜杠表格符号清零；单段 ≤200 字；多音字清单发布前过一遍。

## 4. 任务拆分（批准后创建，3 个任务）

| 任务 | 内容 | owner | reviewer | 依赖 |
|---|---|---|---|---|
| T001 | README + 01 + 02（含把 `discussion/` 快照移入 `_archive/`） | S01 | S02 | 无 |
| T002 | 03 + 06 | S02 | S01 | 无 |
| T003 | 04 + 05（与 02 的协议逐条对齐） | S02 | S01 | T001 done |

- 一个可交付模块 = 一个任务；T001 是核心件（02 决定其余文件的一致性），T002 与 T001 无内容依赖，可并行；T003 必须读 T001 的 02 才能写对，故设依赖。
- 用人：保持 2 人（S01、S02）。理由：批准后存在两条互不依赖的文件组（模板核心 / 压缩与选题），且需要交叉审查；在默认 2 人上限内，不扩编。

## 5. 边界

- 允许写入：`F:\Desktop\Study\#Project\Scheme_Design\` 下 README.md、01–06 文件、`_archive/`。
- 禁止：改写工作站目录；删除 `discussion/` 内文件（只能移动并保留）；生成音视频；写入任何真实书名、真实作者生平、真实引文；其它 owner 的文件。
- 示例与所有模板中的书必须是虚构的，文件头必须有醒目声明。

## 6. 验收标准

统一标准（每个任务都适用）：

1. **数字自洽**：README/01/02/04/05 中出现的时长、字数、S5 占比、±8%、±1.0 分钟、槽位秒数必须与第 2 节完全一致；任一处不符即 fail。
2. **模板可执行（干跑）**：把 02 完整贴给一个没有本书背景的 AI，加上 05 的虚构输入，3 轮内产出 `MODE` + 参数表 + OUTLINE；不得出现正文标记、串模（叙事稿出现“收获/感悟”段）、或素材缺失时仍出稿。审查者执行并留证据。
3. **05 示例**：800–1200 字；文件头虚构声明；含 S1/S2/S5 三段与一份失败 QC 及逐条修法。
4. **04 质检**：AI_SELF_CHECK 恰好 6 项且每项要求附命中原文；HUMAN_CHECK 恰好 5 项；阈值与 02 一致。
5. **06 选题**：30 本池表（书/类型/素材状态三列）、每周批量流程、“没读透、没素材不讲”硬规则、素材来源与版权边界。
6. **工作区结构**：根目录只有 README + 01–06；`discussion/` 已移入 `_archive/discussion/` 且内容完整。

每个任务另附自己的分项验收（写入任务卡）。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 模板文件过长，用户 AI 一次读不完/输出截断 | 02 采用执行协议（第 0 轮只出 OUTLINE、每次 1–2 段）；关键约束前置在第 0 块 |
| 数字在 7 个文件间漂移 | 01 为数字唯一来源；02/04/05 引用同一张表；验收第 1 条逐处核对 |
| 推定语速被当实测 | 全文只写“推定/预计”，实测字段留给用户前 3 期 |
| 示例被当真书评 | 虚构声明 + 禁止真实书名/引文（违者 fail） |
| 日更断更 | 06 选题池——没读透、没素材的书不讲 |

## 8. 估算（预计值，非实测）

- 流水线单期：选题 5 分 + 素材 20 分 + 生成 30 分 + TTS 与出片 20 分 + 发布 10 分 ≈ 85 分钟（首期含压卡另计）。
- 本方案实施：3 个任务、2 人、约 2–3 小时；成本预计 $2–4（项目累计已用约 $1，预计总额 ≤$5）。
