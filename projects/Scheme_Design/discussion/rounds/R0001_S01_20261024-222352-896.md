# 10–20分钟书籍解说音频稿完整设计提案（单骨架+双模式）

# S01 第一轮提案：10–20 分钟书籍解说音频稿设计

> 状态：讨论稿（非交付物）。所有数字是 V1 拟定基线，待 S02/MGR 评审后进方案。

## 0. 一句话主张

**一套“共享骨架 + 模式模块包”的单模板**：6 个时间槽位固定不变，`book_type` 只切换正文组织方式、收尾任务和语速/剧透默认值；字数由目标时长反推，先定预算再写稿。

## 1. 基准参数（先统一口径）

- **语速基线**：270 字/分钟（含自然停顿的实测口径）。文学/思想类 **250 字/分**（需要留白、克制），叙事/网文 **290 字/分**（信息密度高、节奏快）。
- **校准**：前 3 期用 TTS 实测，得个人系数 `k = 实际分钟 ÷ (字数 ÷ 270)`，之后按 k 修正预算。
- **默认时长**：15 分钟。10 / 20 分钟是“减块 / 加块”的缩放版，不是等比注水。
- 音频稿按“分段 + 时间码 + 每段字数上限”写，不依赖字幕、镜头、画面。

| 目标时长 | 文学类字数（@250） | 叙事类字数（@290） |
|---|---|---|
| 10 分钟 | 2300–2700 | 2600–3100 |
| 15 分钟 | 3400–4100 | 3900–4700 |
| 20 分钟 | 4500–5400 | 5200–6100 |

## 2. 结构骨架（15 分钟基准，6 槽位）

| 槽位 | 时间 | 任务 | 文学类字数 | 叙事类字数 |
|---|---|---|---|---|
| S1 钩子 | 0:00–0:50 | 具体冲突 / 反常识问题 / 书里最扎人的一句话；不自我介绍、不报书名全称 | 190 | 240 |
| S2 坐标 | 0:50–2:30 | 这本书是什么、作者（≤3 个事实）、为什么今天讲、听完能带走什么 | 400 | 480 |
| S3 主体一 | 2:30–6:30 | 文学：核心处境与人物；叙事：世界观 + 主角目标 + 最初阻力 | 1000 | 1160 |
| S4 主体二 | 6:30–11:00 | 文学：3 个关键场景支撑一个命题；叙事：冲突升级 + 4–6 个关键节点 + 关系变化 | 1125 | 1300 |
| S5 收束 | 11:00–14:30 | 文学：带来什么 / 学到什么 + 3 个问题；叙事：结局处理（按剧透策略）+ 爽点复盘 + 适合谁 | 875 | 1015 |
| S6 固定尾 | 14:30–15:00 | 一句签名 + 一个互动问题 + 下期预告 | 75 | 85 |
| **合计** | **15:00** | | **3665** | **4280** |

**缩放规则**：
- 10 分钟：S1 40s / S2 70s / S3 150s / S4 180s / S5 130s / S6 30s，总字数约 2500（文学）/ 2900（叙事）。
- 20 分钟：S1 60s / S2 120s / S3 330s / S4 360s / S5 300s / S6 30s，总字数约 5000（文学）/ 5800（叙事）；多出的时间只加“关键节点/关键场景”，不加总结段。

**每 2–3 分钟必须有一个“小结或转折”**，这是单图长音频防走神的硬约束。

## 3. 双策略如何在一套模板里分流

模板分两层：

- **不变层（骨架）**：6 槽位、时间/字数预算、口语化规则、钩子规则、禁用词、字数校验、结尾三件套。
- **可变层（模块包）**：由 `book_type: literary | narrative` 选择，只替换 S3/S4 组织方式、S5 收尾任务、语速与剧透默认值。

| 维度 | 文学 / 思想类 | 叙事 / 网文类 |
|---|---|---|
| 主体组织 | 主题—论证式：处境 → 冲突 → 选择 → 代价 | 事件链式：目标 → 阻力 → 升级 → 高潮 → 结局 |
| 组织单位 | 每个情节服务于一个命题 | 每个事件必须“改变了什么” |
| 人物 | 3–5 人，功能化（谁代表什么） | 5–7 人，动机清晰，其余用身份指代 |
| 收尾 | 3 个问题 + 一句可带走 + 主播自己的判断 | 结局（按策略）+ 爽点复盘 + 适合谁 |
| 情绪曲线 | 慢、留白、克制 | 快、节点密集，90–120 秒一个小高潮 |
| 语速 | 250 字/分 | 290 字/分 |
| 剧透默认 | 讲结局（主题需要） | **不讲结局**，只讲“为什么值得看” |
| 素材依赖 | 原文关键段落、象征、评论 | 分卷卡、人物表、名场面 |

**分流机制**：只维护一个主模板文件，`strategy` 是枚举字段，运行时替换 §主体模块 / §收尾模块 / §默认参数；全局规则（口语化、字数、质检）改一次两模式同时生效。另留 `mode_override`（如传记、游记、科普书走文学骨架但收尾换成“三个收获”），V1 只作为结构建议，不承诺覆盖全部类型。

## 4. AI 生成模板：输入 / 输出字段草案

### 输入（YAML，一次填完）

```yaml
meta:
  title: 书名
  author: 作者
  book_type: literary | narrative
  sub_genre: 现实主义 / 科幻 / 玄幻 / 都市 …
  word_count: 3000000
  status: 完结 | 连载
  target_duration_min: 10 | 15 | 20
  speed_cpm: 250 | 290
  spoiler_policy: no_ending | ending_ok
  tone: 冷静克制 | 热血 | 幽默
  audience: 目标听众一句话
account:
  persona: 主播人设（一句话）
  signature_close: 固定结束语
  cta: 收藏/关注/评论引导
materials:
  logline: 一句话主线
  must_include: [必须讲到的 3–5 件事]
  must_avoid: [不讲的内容]
  key_quotes: [{text: "≤50字", location: "第X章 / 第X页"}]
  volume_cards: []        # 叙事类：L1 分卷卡
  character_table: []     # 人物：名字 / 身份 / 目标 / 结局是否可讲
  theme_notes: []         # 文学类：主题、象征、争议点
constraints:
  banned_phrases: [首先, 其次, 综上所述, 不得不说, 在这个快节奏的时代, 让我们一起]
  max_sentence_len: 45
  max_quote_chars: 50
  sensitive_topics: []
```

### 输出（一个 Markdown，四块）

1. `OUTLINE`：一句话主张 + 6 槽位计划表（目的 / 要点 / 字数 / 时长），先自检字数总和。
2. `SCRIPT`：按 `## [00:00–00:50] 钩子` 分节，纯口播文本；允许 `[停]`、`【重音】` 标记；每节末尾标字数与累计时长。
3. `QC`：自动检查（字数、禁用语、平均句长、剧透、结构完整度），逐项给 通过/不通过。
4. `FACT_CHECK`：列出稿中所有“需人工核对”的事实（作者生平、人物结局、引文出处），供 5 分钟人工复核；缺素材时写【待核】，**禁止凭记忆补细节**。

### 生成步骤（写进提示词）

先出 OUTLINE →（可人工确认）→ 逐段写 SCRIPT，每段写完核对字数 → 合并 → 输出 QC + FACT_CHECK。任何一段超预算，先删“解释性内容”，不删“具体细节”。

## 5. 几百万字网文的压缩方法（L0–L4 分层漏斗）

| 层 | 产出 | 格式 / 上限 |
|---|---|---|
| L0 | 元信息表 | 书名/作者/状态/分类/主角/金手指/主线一句话，1 页 |
| L1 | 分卷卡 | 每卷 1 张 ≤200 字：起止章、核心冲突、主角状态变化（能力/地位/关系）、新增人物、卷末钩子；10–30 卷合计 2000–6000 字 |
| L2 | 关键节点卡 | 每卷 3–5 条，每条 ≤60 字，格式“谁—想做什么—遇到什么—结果改变了什么” |
| L3 | 三线大纲 | 主线（目标/阻力/代价）、关系线（≤5 人）、爽点线（每卷 1–2 个名场面），≤1500 字 |
| L4 | 口播稿 | 只取 L3 的 6–10 个节点，约 4300 字 |

**防流水账的五条筛选规则**：
1. **状态变化测试**：不改变主角目标/能力/关系/世界规则的事件一律删。
2. **重复删除**：同类打怪、升级、副本只留“第一次”和“最难的一次”。
3. **因果链**：每段结尾必须能接“所以……”，接不上就删。
4. **数量上限**：15 分钟最多 6–8 个情节点、5–7 个人名；人物超了合并成身份指代。
5. **六锚点**：开局 / 第一次转折 / 中点 / 至暗 / 高潮 / 结局，按锚点讲，不按章节顺序讲。

**压缩比目标**：300 万字 → 5000 字分卷卡（约 1:600）→ 1500 字大纲 → 4300 字口播。L3 大纲建议先人工扫一眼再写稿，这一步最省返工。

## 6. 日更质检清单（发布前 5 分钟）

- [ ] 字数落在区间，估算/实测时长 10–20 分钟，误差 ≤1 分钟
- [ ] 前 15 秒出现具体钩子（不是“今天给大家讲一本书”）
- [ ] 每 2–3 分钟有一个小结或转折
- [ ] 文学类：结尾有 3 个问题 + 1 句带走 + 明确观点；叙事类：没有“收获/感悟”段
- [ ] 书名/作者/人物名/结局与素材卡一致，【待核】残留 = 0
- [ ] 引文单处 ≤50 字、总引用 ≤300 字，且标出处
- [ ] 禁用词命中 = 0；平均句长 ≤25 字，最长句 ≤45 字
- [ ] 无“如图/如下表/大家可以看到”这类依赖画面的表达；数字口语化
- [ ] 剧透符合 `spoiler_policy`
- [ ] 敏感内容（暴力/性/自伤/政治）已按平台规则过一遍
- [ ] 文件名 `YYYYMMDD_书名_类型_vN.md`，开头含字数/时长/类型元信息

## 7. 交付文件组织（V1，6 个文件）

```text
Scheme_Design/
  README.md               3 步跑通一期：选书 → 填输入 → 生成 + 质检
  01-方案总纲.md           设计原则、6 槽位结构表、字数预算、双策略差异、风险与边界
  02-主模板.md             唯一提示词模板：输入字段 + 输出格式 + 两套模块包 + 生成步骤
  03-长文本压缩SOP.md      L0–L4 分层法、分卷卡/节点卡模板、五条筛选规则
  04-质检清单.md           发布前检查表（阈值 + 常见问题）
  05-使用示例.md           虚构书的输入 YAML + OUTLINE + 前两段 SCRIPT 节选（非真实书评）
```

**理由**：日更场景下用户只打开 1–2 个文件；`templates/` 目录和 JSON Schema 留到 V1.1，V1 把字段说明内嵌在 02 里，减少文件数。讨论稿目录 `discussion/` 不算交付物，最后清理或保留由 MGR 定。

## 8. 主要风险

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | **事实幻觉**（最高） | 编造作者生平/结局/名句，掉粉且不可挽回 | 素材卡先行；输出 FACT_CHECK；双源核对；模板禁止凭记忆补细节 |
| 2 | **版权** | 长段引用/搬运原文被投诉 | 单处 ≤50 字、总引 ≤300 字；改写复述；标出处；不逐章翻译式复述 |
| 3 | **时长不稳** | 字数≠实际时长，10 分钟变 17 分钟 | 前 3 期 TTS 实测校准 k；首段先试听 |
| 4 | **同质化 / AI 味** | 每期一个味，听众流失 | 钩子 8 型轮换；每期 ≥1 个主播自己的判断；禁用词表 + 句长限制 |
| 5 | **日更产能** | 每期 2–4 小时不可持续 | 批量压卡（一次 5 本）；选题池 ≥30 本；80% 工作前置 |
| 6 | **网文流水账** | 压缩层没做好，讲成章节复述 | 状态变化测试 + 六锚点 + 节点上限；L3 大纲先审再写 |
| 7 | **剧透误伤** | 叙事类讲结局导致弃看 | `spoiler_policy` 默认 no_ending，结尾钩子不剧透 |
| 8 | **模板绑架** | 诗集/学术/传记强行套两类会失真 | V1 明确只覆盖两类；`mode_override` 只给结构建议，不承诺全类型 |
| 9 | **平台合规** | 敏感题材限流/下架 | 敏感清单 + 发布前人工过一遍 |
| 10 | **单图注意力流失** | 长音频听不下去 | 口播自带“听觉章节”：每 3 分钟一句小结 + 语气变化；字幕/配图留 V2 |
